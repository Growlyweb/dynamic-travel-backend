1. Customer (B2C)

Register, then enter the 6-digit code. If EmailJS is not configured the code is printed in the server terminal (look for [mail:console]).

Register POST /api/auth/register

Try adding a role in your head: the server ignores it. Password needs 8+ chars with upper, lower, number, symbol.

Verify email code POST /api/auth/verify-otp

Login (any role) POST /api/auth/login

Use the seeded admin here to unlock the Admin section. Wrong passwords always answer Invalid credentials.

2. Firebase sign-in (B2C)

Sign in with Google. Firebase proves who you are, then the API issues its own tokens (POST /api/auth/firebase). Email and password is not done through Firebase: use the Register and Login forms.

Paste the apiKey once; it is remembered in this browser.

More options (project settings, switch Google account, paste a token)

The API accepts Google only. A token from Firebase email and password is refused with FIREBASE_PROVIDER_NOT_ALLOWED; for email and password use the Register and Login forms above.

3. Agency (B2B)

Multipart form. A trade license file is required; business card and other files are optional (PDF, JPEG, PNG or WEBP, up to 5 MB).

Register agency POST /api/auth/b2b/register

After this, verify the code with the Verify email code form in section 1 using the agency email. Then try the operational route below: it stays closed until an admin approves.

4. Session

Uses whoever is signed in (see the top bar). The access token is sent as a Bearer header.

To see rotation: click Refresh twice, then replay an old token (mobile mode, paste an old refresh token below) and watch every session die.

Refresh with a pasted token (mobile mode) POST /api/auth/refresh

Change password POST /api/auth/change-password

Other devices are signed out; this one gets fresh tokens. Limit: 5 tries per 15 minutes.

5. Forgot password

Request a code POST /api/auth/forgot-password

Always answers the same, even for unknown emails. Limit: 3 per hour.

Check the code (does not use it up) POST /api/auth/verify-reset-token

Set the new password POST /api/auth/reset-password

6. Invited staff / admin: set first password

An admin creates the account (section 7); the emailed link carries a token (also printed in the server terminal as .../setup-account?token=...).

Activate account POST /api/auth/setup-account

7. Admin (login as the seeded admin first)

Click an id chip on the right, with a field focused, to paste it in.

Find users GET /api/admin/users

Create staff (sends invite) POST /api/admin/staff

Edit someone's profile PATCH /api/admin/users/:id

Only an admin can do this. Try it signed in as a customer, an agency or staff: every one gets 403.

Edit an agency's business record PATCH /api/admin/b2b/:id

Change status PATCH /api/admin/users/:id/status

Suspend someone who is signed in elsewhere: their token stops working on the next request.

Set staff permissions PATCH /api/admin/users/:id/permissions

Approve or reject an agency PATCH /api/admin/b2b/:id/approval

Approval needs a trade license on file. Verify the document first if you like (next form).

Verify or reject a document PATCH /api/admin/b2b/:id/documents/:docId

8. Role areas and private documents

Each button works only for its own role. Try them with the wrong role to see the 403.

Update my profile (try sneaking in a role) PATCH /api/b2c/profile

B2B: upload more documents POST /api/b2b/documents

Download a private document GET /api/documents/partners/:partnerId/:docId

Owner, admin and permitted staff get the file. Anyone else gets 404, as if it does not exist.
